# Phase 1 Agent Workflow Non-Inferiority Pilot

This document defines the Phase 1 comparison. It does not claim that the pilot
has passed. Quality results must be recorded before reading-savings results.

## Fixed comparison

Run every task in separate, uncontaminated contexts against the same commit,
task text, change boundaries, tests, architecture invariants, and static checks.

| Track | Initial context |
| --- | --- |
| Baseline | Repository instructions and the normal broad-context workflow |
| Librarian | Canonical bootstrap, explicit profile selection, and bundle |

The five pilot tasks are:

1. Repeated approval returns the wrong message.
2. Dispatcher reports success without execution evidence.
3. An explicit request routes to the wrong handler.
4. Business Outcome maps to the wrong reasoning state.
5. A completion claim conflicts with available evidence.

Codex and Claude Code must independently run the Librarian track. Store the raw
suggestion output, selected profile, commit, bundle SHA-256, bundle size, and
workflow-gate status. Identical inputs must produce identical bundles.

## Independent Authority Gold Set

Before each solution, an independent reviewer with full repository access must
define the material code, definitions, imports, callers, callees, adapters,
schemas, flags, persistence readers/writers, tests, renderers, approval paths,
evidence consumers, architecture contracts, authority documents, and production
evidence. The reviewer must not derive this set from the bundle.

Compare every source actually opened with this gold set. For a shared identifier
or a change spanning layers, attach a Cross-Layer Impact Matrix containing:
layer, owner, input, output, source of truth, callers, consumers, approval
boundary, evidence boundary, user-facing effect, tests, and duplicate-ownership
risk.

## Per-run record

Record these fields for both tracks:

- agent, task, track, commit, task text, and selected profile where applicable;
- tests, architecture gates, static checks, and functional defects;
- gold-set misses, cross-file/layer misses, and architecture defects by severity;
- architecture corrections, material context corrections, and first-pass result;
- every context expansion: source, reason, discovery path, necessity, recurrence;
- files opened and source bytes/tokens read.

An independent full-repository review should be blind to the track where
practical. It must look for duplicate ownership, parallel sources of truth,
approval bypass, hidden routing or reasoning changes, claim/evidence mismatch,
planning treated as current main, missing callers/consumers/schemas/flags, work
in the wrong layer, and unsupported production claims.

## Evaluation order and acceptance

Evaluate tests and architecture gates first, followed by functional defects,
gold-set misses, cross-file/layer misses, architecture defects, review
corrections, context corrections, first-pass acceptance, and context expansions.
Only after every quality gate passes may the report reveal files, bytes, context
size, or estimated token savings.

Acceptance requires identical Codex/Claude bundles for the same explicit
profile and commit; no silent selection; zero material authority misses; zero
Critical/High architecture defects; baseline-equivalent tests and architecture
gates; no increase in functional defects or material corrections; every
material external dependency recorded; zero excluded-layer leakage; independent
review of every solution; writing quality, accuracy, and usefulness no lower
than Baseline; and no runtime or production change.

Any quality failure is a regression regardless of reading savings. Five tasks
permit only a cautious manual rollout, not a general statistical quality claim.

This run advances the 27/07 preflight from "4/5 STOP, 1/5 preliminary" to "5/5
PROCEED, 5/5 with an independent Gold Set, a completed Librarian-track

themselves, which are left as-generated for the audit trail.

**Independence model used (per explicit user instruction — "use an
independent subagent" — this session's closest achievable approximation of
the pilot doc's independence requirement):** for each of the 5 tasks, a fresh
`Agent` subagent with no access to this conversation, the Librarian bundle,

only one track run here, not a Baseline-vs-Librarian comparison per task),
and it does not satisfy the dual-vendor Codex/Claude-Code bundle-hash-equality

**No runtime or production change was made in this run for any of the 5
tasks** — three tasks surfaced real, gold-set-confirmed defects
(`approval_ux`, `tool_execution`, `turn_coordinator_routing`), all three
sitting inside territory `docs/architecture/CROSS_LAYER_AUTHORITY_CONTRACT_V1.md`

#### What remains unproven (unchanged in kind from 27/07, now with more data)

- **Codex/Claude-Code dual-vendor bundle-hash equality**: still not
  attempted. This session used Claude Code only; no Codex run exists for
  today's bundles.
- **Baseline-track comparison**: today's run is Librarian-track only for all
  5 tasks (the 27/07 preflight's one Baseline-vs-Librarian comparison, for

- **"Blind to the track" independent review**: satisfied in spirit (each
  blind reviewer had no access to this conversation and had to independently
  verify or refute both the Gold Set and the investigation using its own
  repository reads) but not in the doc's literal sense, since there is only

  and today's results — 1 clean pass, 1 Critical process failure, 2 High
  misses, several Medium findings — argue for more caution, not less, before

**Phase 1 acceptance is still not established.** The honest summary of this
