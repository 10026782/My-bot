# SCOREBOS Reference Candidates

This is a shortlist for later UX synthesis, not a final design decision and not a change to the approved Constitution.

## Strongest observed candidates

### 1. Context-preserving entity work — Linear

`OBSERVED`: issue detail keeps status, ownership, labels, activity and contextual AI near the entity.  
**Mapping:** DEC-UX-09, DEC-UX-11, DEC-UX-14.  
**Reuse:** `MAP TO EXISTING SCOREBOS PATTERN`.  
**Why:** supports the Constitution's continuous lifecycle and reduces root-navigation resets.

### 2. Global quick action / command entry — Linear + Raycast

`OBSERVED`: Linear exposes search/create in the product shell; Raycast presents a fast verb-oriented launcher model.  
**Mapping:** DEC-UX-02, DEC-UX-06, DEC-UX-07.  
**Reuse:** `MAP TO EXISTING SCOREBOS PATTERN` for global create/search; Raycast's keyboard-first behavior remains `SYSTEM-LEVEL PATTERN CANDIDATE` until device/context fit is validated.

### 3. Business-field collection — Attio

`OBSERVED`: public demo combines company records with ICP scores and owners.  
**Mapping:** DEC-UX-09, DEC-UX-10.  
**Reuse:** `USE AS COMPOSITION INSPIRATION`.  
**Why:** helps make datasets useful for comparison and next action without inventing a new entity model.

### 4. Explicit working/readiness state — Retool

`OBSERVED`: prompt entry visibly distinguishes an empty/disabled submit state from an active input surface.  
**Mapping:** DEC-UX-12.  
**Reuse:** `MAP TO EXISTING SCOREBOS PATTERN`.  
**Why:** reinforces clear working, readiness and feedback states.

### 5. Public lifecycle grouping as an inspection candidate — monday CRM + Pipedrive

`OBSERVED`: monday exposes revenue lifecycle stages and role-specific agent panels in a public demo; Pipedrive exposes product/feature groupings around activity-based selling and lead-to-deal work.
**Mapping:** DEC-UX-09, DEC-UX-10, DEC-UX-11.
**Reuse:** `USE AS COMPOSITION INSPIRATION` only; authenticated workflow states remain unverified.
**Why:** candidate for later comparison of lifecycle framing and domain grouping, without deciding SCOREBOS navigation or screen architecture.

### 6. Visible readiness and tool grouping — JSON Crack + BentoPDF

`OBSERVED`: JSON Crack exposes a compact editor shell with `Valid` and `Live Transform` states; BentoPDF exposes searchable tools plus explicit compact/full-width display controls.
**Mapping:** DEC-UX-07, DEC-UX-12, DEC-UX-16.
**Reuse:** `MAP TO EXISTING SCOREBOS PATTERN` for readiness/search; `USE AS COMPOSITION INSPIRATION` for density controls. The density pattern is a `SINGLE-REFERENCE CANDIDATE` until validated with SCOREBOS operators and responsive evidence.
**Why:** these public states show how a tool-rich system can make readiness, discoverability and density choices visible without adding a new domain model.

## Not candidates yet

No pattern from Intercom, Airtable Interfaces, Stripe, HubSpot, Notion, Vercel, Figma, Tana, Hoppscotch, RAWGraphs, CSV Repair or Excalidraw is shortlisted because the required stable rendered product state was not verified. Pipedrive and monday are listed only as public-example candidates with explicit evidence boundaries.
