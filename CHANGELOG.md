# Changelog

All notable repository-level changes should be recorded here.

## Unreleased

- Added `scripts/classify_contacts_for_airtable.py` — single-file (CSV/VCF) contact classifier for Airtable import, built on top of `contact_merge.py`'s existing parse/dedup logic (`parse_google_csv`/`parse_vcf`/`merge_contacts`, imported directly rather than duplicated). Classifies each contact's `Type`/`Role Category` by keyword match on name (`עו"ד`→Lawyer/expert, `רו"ח`→Accountant/expert, `ספק`/`יבואן`→Supplier/supplier, `שותף`→Partner/partner, `משקיע`→Client/investor, default Client/lead), tags every row with the `--owner`/`--referred-by` CLI args, and writes a `contacts_classified.csv` + `report.txt` (counts, dedup delta, per-Type breakdown) into `--outdir`. **Note:** `Owner` and `Referred By` are not existing fields on the live `Contacts` table (`ContactFields` in `airtable_schema.py`) — the script writes them as output-only CSV columns and prints a warning; add the fields in Airtable (or drop the columns) before import. Verified against a real 1345-contact `.vcf` export (1338 after dedup) in a temp directory — no contact PII committed to the repo. Added `output/`, `contacts_merged.csv`, `*.vcf` to `.gitignore` to prevent future accidental commits of contact exports/derived CSVs.
- Added `contact_merge.py` — standalone offline CLI merging Google Contacts CSV exports and vCard (`.vcf`) files into one Airtable-`Contacts`-ready CSV, deduping by normalized Israeli phone number (PR #88). Admin/import utility — no dispatcher/identity wiring, writes a local CSV for manual import. Fixed a real bug found during review: vCard line-folding (RFC 2425 continuation lines) was dead code (a no-op `pass`), silently truncating wrapped field values — replaced with a proper unfold pass.
- F13 (`core/tenant_config.py` + `providers/{__init__,interfaces,airtable_shim,anthropic_shim,twilio_shim}.py`) — code written and merged (PR #87), **not wired into the live pipeline** (new files only, zero existing import touched). Registered spec-only in `ROADMAP.md` first; the original spec assumed function signatures that don't exist in this codebase (`gateway_add`/`gateway_update`/`gateway_delete`, `send_via_cog`, `airtable_get(max_records=...)` returning `list[dict]`, `_validate_twilio_signature(headers, body)`) — corrected against the real signatures (`airtable_create`/`airtable_patch` + `_resolve_table()`, `send_outbound(OutboundEnvelope)`), logged as `BUG_AUDIT_LOG.md` SPEC-001. F12/F13 overlap on a `providers/` directory is still undecided — do not wire either into the pipeline before that decision.
- Added `inbound_handler.py` (F06) — unified inbound lead gate sitting in front of `lead_capture.py`: dedups by `external_id` (exact, e.g. `gmail:<msg_id>`), updates existing leads by `sender_id`, otherwise creates a new email lead. Added `LeadFields.EXTERNAL_ID`/`SENDER_ID` to `airtable_schema.py`. Rewired `email_inbound.run_email_poll()` to route through the new gate instead of building/approving drafts directly; added `_alias_to_domain()` (To-address → business domain) and `InboundEmail.to` (the Gmail `To` header wasn't previously fetched — without it, domain routing would have always fallen through to `general`). `scheduler.py` already had `_job_email_inbound` wired to `run_email_poll()` — no scheduler change needed. Added `test_inbound_handler.py`. **Manual step required before enabling `EMAIL_INBOUND`:** add `external_id` and `sender_id` (Single line text) to the Airtable `Leads` table, then refresh `schema_cache.json` (`schema_audit.py`) — confirmed via a local test run that `airtable_gateway` currently drops both fields as "unknown field ... not in schema_cache". **Update:** both fields have now been added to the live `Leads` table (verified via Airtable MCP: `external_id` = `fldNAXOruq53qxYKH`, `sender_id` = `fldyEHy5Udasl3G02`); `schema_cache.json` updated to match (targeted addition, not a full `schema_audit.py` resync — no live Airtable credentials in this sandbox to run that script).
- Added `docs/operations/DEPLOYMENT.md` — deploy guide for Render + Vercel.
- Added `docs/operations/RUNBOOK.md` — incident response for 6 common failure scenarios.
- Updated `README.md` — added WhatsApp channel, Twilio env vars, operations docs to documentation map.
- Added Screen Filter Gateway (`SCREEN_CONFIGS` + `_build_formula()`) to `tma_api.py` — `GET /api/leads` now supports `?view=active|monitoring|all`; `_get_project_cards()` / `get_project_dashboard()` wired to the same lead-filtering config (PR #75).
- O4 Finance Pulse + Payments/Expenses migration (`airtable_schema.py`, `tma_api.py`): `Tables.PAYMENTS`/`EXPENSES` and `PaymentFields`/`ExpenseFields`/`PaymentStatus` now use the English field names live in Airtable (manual migration done ahead of this change — verified against the live base via Airtable MCP). `finance_pulse()` rewired onto `SCREEN_CONFIGS["finance_pulse"]` + `_build_formula()` (matching the existing `/api/leads` pattern) — now supports `?view=active|overdue|all` and returns `available_views` in the response. Updated `smoke_tests.py`'s stale Hebrew-field assertions for `Tables.PAYMENTS`/`PaymentFields.STATUS`/`DATE` to match. **Update:** user manually renamed `Payments.Domain`/`Expenses.Domain` → lowercase `domain` and `Expenses.Status` → lowercase `status` directly in live Airtable; re-verified via Airtable MCP and updated `ExpenseFields.STATUS` in `airtable_schema.py` to match (was hardcoded to capital-S `"Status"` per the original spec note, now stale) — this resolves the `_build_formula()` domain case-mismatch previously flagged below. **Known gaps, not fixed in this change (out of spec scope):** `PaymentFields.CONTACT`/`NOTES` (`contact_id`/`notes`) point to fields that don't exist on the live `Payments` table — `crm.py`'s `create_payment()` will fail with an Airtable "unknown field" error if ever called with `contact_id` or `notes` args.
