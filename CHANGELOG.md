# Changelog

All notable repository-level changes should be recorded here.

## Unreleased

- **C89-RAW-OBS** (PR #224): `IngressClassification.raw_ref` was permanently empty, and `classify_ingress()` never recorded its own classification decision. Now, for every call across all tiers (1-5), `classify_ingress()` saves the raw text to `Tables.DECISION_INBOX` behind a new `FEATURE_RAW_CAPTURE` flag (default off, always returns a non-empty `raw_ref` — a local fallback ref when the flag is off or the write fails) and records an `AgentObservation` (`kind="capture_classification"`) via `ActionGateway`'s existing `record_agent_observation(contract_id=None, ...)` API only — no changes to `ActionGateway`'s core. 14 new tests.
- **BUG-C89-TIER4-PRECEDENCE** (PR #223): `core/ingress_classifier.py`'s `_is_tier4()` (the single Tier-4 gate reused by `router.py` and `lead_candidate_handler.py`) missed several classes of pasted export/status output — CSV/Hebrew table headers without an explicit separator, fixed-width tables, and Airtable status/score readouts (`Status:`, `Score:`, `View in Airtable`, `memory_key`/`@lead`, `owner_dictation`) — which were misclassified as lead dictations and reached the Agent/ActionGateway. Extended the marker set; scoped the bare `"airtable"` marker to require other pasted-content structure so an explicit system-check command still reaches the real `SYSTEM_STATUS` check. 13 new tests.
- **BUG-C89-APPROVAL-IDENTITY** (PR #222): `ActionGateway.propose_action()` was called with `origin_chat_id=identity.memory_key` (e.g. `"boss_hq:eliyahu"`) instead of a real channel external_id. On approval, the dispatch executor re-resolved identity via `resolve_identity(origin_channel, origin_chat_id)`, missed the registry lookup, and silently fell back to `readonly` — so an owner-approved action (e.g. confirming "כן" on a Leads update) was denied by the dispatcher as if a readonly user had requested it. `ActionContract` now preserves the actor identity (role/external_id/tenant/user/domain) resolved at propose time via a new optional `identity=` param; the executor uses it directly instead of re-resolving, with legacy contracts falling back to `resolve_identity()` as before. Also: the C89 lead-write preview now says "מצאתי ליד קיים. לעדכן אותו?" instead of the generic "לשמור?" when the candidate matches an existing lead, and updates to an existing lead always require approval — even when `FEATURE_AUTO_CAPTURE=true`. 37+9+44 tests passing.
- **BUG-SESSIONS-ROOT** (PR #221): `session_store.py`'s Session lookup used to parse `airtable_get()`'s human-formatted string output via regex; any lookup failure (network error, parse miss, unexpected shape) was treated as "not found," letting `_sync_to_db()` unconditionally POST a new Session record even when one already existed — silent duplication on every flaky lookup, not just genuinely empty ones. Added `airtable_get_records()` to `tools/airtable_tools.py` (structured, paginated, raises on HTTP/contract failure) and rewired `session_store.py` to validate records structurally; POST is now only allowed after a confirmed zero-record lookup — any other outcome fails closed. 49 internal + 4 new pytest tests (`test_session_store_contract.py`).
- **BUG-IC-01B** (PR #220): `core/router/intent_router.py`'s `_AMBIGUOUS_PHRASES` (BUG-048/BUG-IC-01) only matched bare ambiguous phrases ("סטטוס", "למלא משימות"); natural-language prefixes ("אני צריך למלא משימות", "צריך סטטוס", "תעזור לי ...") fell through to `Intent.UNKNOWN` → `Handler.AGENT` with full tool access instead of a clarifying question. Added 3 prefix-tolerant patterns reusing the same disambiguation questions. 6 new test cases, 44/44 passing.

- fix: real self-test execution for `test_document_converter.py` via `__main__` guard (BUG-049 / BUG-CI-SILENT-PASS-DOCUMENT-CONVERTER) — CI now actually runs the 6 assertions instead of false-passing. `ci.yml` runs `test_*.py` files as plain scripts (`python "$f"`), not through `pytest`; the pytest-style test functions here (all depending on the `tmp_path` fixture) previously never executed under that invocation, so `python3 test_document_converter.py` silently exited 0 with zero assertions run. Added an explicit `__main__` block calling each of the 6 test functions against a real `tempfile.mkdtemp()` dir (no auto-collect, since `tmp_path` has no plain-Python equivalent); `pytest.importorskip` calls are caught separately as skips. No changes to `ci.yml` or `document_converter/` itself. Verified: 6/6 run for real (`python3 test_document_converter.py`), a deliberate `assert False` break produces a real non-zero exit, and `pytest test_document_converter.py` remains 6/6.

- **C89 Stage 3 Capture Policy + BUG-NEW-12 + BUG-IC-01** (PR #203): (א) `core/ingress_classifier.py` (new) — `IngressClassification` (generic input contract, mirrors `ActionContract` on the output side) + `classify_ingress()` as the single entry point for text-input classification (Tier 1 SIMPLE_CAPTURE / Tier 2 CLEAN_BATCH / Tier 3 MIXED_BATCH / Tier 4 EXPORT-TABLE-LOG — never auto-write / Tier 5 UNKNOWN — falls through). `core/lead_candidate_handler.py` now classifies before parsing. `FEATURE_AUTO_CAPTURE` (default off) gates auto-write; no behavior change in production until explicitly enabled. (ב) BUG-NEW-12: `session_store.py`'s `_find_record_id_in_db` matched a generic `rec\w+` regex that could pick up record IDs embedded in State JSON instead of the Session record itself, missing existing sessions and causing duplicate `airtable_add` calls (14 duplicate rows observed live for one sender) — replaced with `_SESSION_RECORD_RE` scoped to `• [recXXX]` bullet markers; new `_find_best_session_in_db()` always prefers PATCH when any record is found, with explicit `found_count`/`selected`/`action` logs. (ג) BUG-IC-01: bare owner phrases ("סטטוס", "בדיקות מערכת", "מה המצב", "למלא משימות") fell to `Intent.UNKNOWN` → `Handler.AGENT` with full tool access, letting the Agent decide on its own whether to run a live connectivity check — `detect_ambiguous_phrase()` now intercepts these and routes to `Handler.CLARIFY` with a specific disambiguating question instead; explicit action-verb phrases ("בדוק חיבורי מערכת") still route to a real `SYSTEM_STATUS` check.
